# 문구작가 운영 정보 확장안과 수집 SOP

기준일: 2026-08-07  
상태: 조사 자산으로 보존. 세금·해외배송 P1 Notes 1차 적용 완료, 신규 P0 구현은 행사 핵심 지표 검증 뒤로 보류
적용 범위: 행사 데이터 다음에 추가할 작가 운영 정보. 자동 수집·개인화 판정·비교 도구는 별도 승인과 검증이 필요하다.

## 0. 결론

이 문서의 네 계층은 행사 핵심 흐름이 검증된 뒤의 확장 후보이며 현재 승인된
개발 순서가 아니다. 먼저 실제 사용자 5명 이상에게 행사 탐색→비교→저장→준비
흐름을 검증하고, 참가 판단 가능한 회차 15개와 Binder 반복 사용을 확보한다.

그 게이트를 통과한 뒤의 첫 확장은 범용 `Creator OS`나 제작업체 전화번호부가 아니라,
작가가 한 상품을 발주하고 손익을 판단할 때 이어지는 네 가지 데이터층으로 제한한다.

1. **인쇄·후가공 사양 표준사전**: 인쇄 파일, 색, 재단, 소재, 후가공의 공통 개념과 업체별 용어
2. **제작업체 공표 카탈로그**: 같은 사양에서만 비교하는 업체별 옵션·가격·납기 버전
3. **포장·배송 규격·요금 레지스트리**: 공표 소비자 요금과 개인 계약 요금을 분리한 배송 조건
4. **재고·원가·손익 계산기**: 제작·포장·배송·수수료·불량·샘플을 한 시나리오로 계산

```text
표준화된 제작 사양
→ 같은 사양을 제공하는 업체의 현재 공표 조건
→ 포장·배송 조건
→ 출처를 추적할 수 있는 원가·손익 판단
```

이 네 묶음은 각각 `공식 규정`, `업체 공표값`, `작가 입력/경험`을 같은 결론처럼
섞지 않는다. Bindery는 법률·세무·안전 적합성을 대신 판정하거나 업체를 순위화하지
않고, 적용 질문·공식 원문·확인 시점·불확실성을 함께 보여 주는 의사결정 보조 도구가 된다.

### P0 데이터층을 네 개로 제한한 이유

- **A 사양 표준사전**은 거의 모든 발주에서 재사용된다. `반칼`, `완칼`, `도련`,
  `백색 인쇄` 같은 공통 개념과 업체 원문 용어를 함께 보존해야 비교가 성립한다.
- **B 제작업체 공표 카탈로그**는 전화번호부가 아니라 특정 수량·크기·재질·후가공·
  부가세·배송·납기 조건의 버전이다. 필수 차원이 하나라도 없으면 가격순에서 제외한다.
- **C 배송 레지스트리**는 공개 규격과 요금대를 비교적 안정적으로 정규화할 수 있고,
  업체 견적을 실제 수취 원가로 연결한다. 개인 계약요금은 공개값과 물리적으로 분리한다.
- **D 원가·손익 계산기**는 기존 행사 부스비와 새 제작·배송 데이터를 한 판단으로 만든다.
  단위공헌이익이 0 이하이면 손익분기 수량을 숫자로 꾸며내지 않고 계산 불능 이유를 보여 준다.

사업자·세무·KC·저작권·온라인 판매 규정은 오류 피해가 커서 빼는 것이 아니라 P1에서
더 보수적으로 다룬다. 초기에는 자동 판정기나 범용 법률 백과사전이 아니라 적용 질문,
공식 원문, 확인 기한, 변경 알림만 제공한다. 온라인 채널 수수료와 현장 결제는 공개값과
개별 계약값을 분리할 구조가 증명되기 전까지 단일 비교 수치로 공개하지 않는다.

## 3. 사실 계층과 표시 규칙

행사 파이프라인의 S1~S5를 그대로 재사용하지 않고, 목적이 다른 작가 운영 정보용
`CreatorSourceTier`를 둔다.

| 등급 | 정의 | 공개 가능 범위 | 화면 표시 |
|---|---|---|---|
| `G1` | 현행 법령·고시·정부 공식 민원/신고 경로 | 적용 범위, 의무, 법정 기한, 공식 절차 | `공식 규정` + 시행일 + 확인일 + 원문 |
| `G2` | 정부·공공기관의 공식 가이드·FAQ·상담 사례 | 설명과 예시. 법령 자체로 표현 금지 | `공식 안내` + 담당기관 + 확인일 |
| `V1` | 업체·플랫폼이 공개한 사양·요금·정산·납기 조건 | 해당 업체와 옵션 서명에 한정 | `업체 공표` + 업체명 + 기준일 + 예외 |
| `V2` | 로그인 뒤 개인화된 등급·견적·계약 조건 | 공개 카탈로그에 저장하지 않음. 사용자 로컬 입력만 | `내 계약/견적` + 사용자 입력 + 비공개 |
| `E1` | 작가가 제공한 경험·실측·실제 납기·불량 사례 | 동의·표본·익명성 기준 충족 전 비공개 | 공개 시에도 `작가 경험`과 표본/기간을 별도 표시 |
| `D1` | 공식·업체·개인 입력에서 계산한 파생 결과 | 공식 버전과 입력 레코드가 모두 추적될 때만 공개 | `계산 결과` + 계산일 + 공식/입력값 펼쳐보기 |
| `I1` | Bindery 편집자가 작성한 설명·주의사항 | 지원 근거와 검수 시점이 있을 때 공개 | `Bindery 해설` + 적용 범위 + 근거. 공식 문구처럼 표시 금지 |
| `U0` | 검색 결과, 제3자 블로그, 모델 추출, 출처 불명 | 연구 후보만. 공개 필드 근거 금지 | 공개 화면에 노출하지 않음 |

한 문장이나 숫자에 여러 계층을 합성하지 않는다. 예를 들어 `배송 3,500원` 대신
`우체국 공개 요금표의 규격별 요금`, `작가의 계약 요금`, `실제 지출 경험`을 서로 다른
레코드로 둔다. 계산 결과에는 사용한 레코드 ID·기준일·사용자 입력을 펼쳐 볼 수 있게 한다.

### 공통 필드

```text
id, domain, title, jurisdiction, applicability, sourceTier,
sourceIds[], effectiveFrom, effectiveTo, checkedAt, nextCheckAt,
contentHash, extractedFields[], humanReviewer, reviewState,
supersedesId, uncertainty, legalOrCommercialDisclaimer
```

원문 획득 기록은 공개 사실 레코드와 분리한다.

```text
SourceSnapshot: sourceId, fetchedAt, finalUrl, httpStatus, accessContext,
etag, lastModified, rawHash, normalizedHash, mimeType, pageOrSelector,
copyrightPolicy, redistributionPolicy
```

`effectiveFrom`을 알 수 없으면 추정하지 않는다. `checkedAt`은 원문을 마지막으로 열어 본
시각일 뿐 내용의 효력 발생일이 아니다. 접근 성공도 내용 정확성이나 사용자 적합성을
보증하지 않는다.

### 계산 공식 초안

```text
판매가능수량 = 입고수량 - 불량 - 샘플 - 증정 - 파손 - 예약
단위제작원가 = 제작총액 / 판매가능수량
단위변동원가 = 단위제작원가 + 포장 + 결제·채널 변동비 + 판매자부담 배송
단위공헌이익 = 실수취판매가 - 단위변동원가
손익분기수량 = ceil((제작 외 고정비 + 참가비 + 장비비) / 단위공헌이익)
```

판매가능수량이나 단위공헌이익이 0 이하이면 손익분기 수량을 반환하지 않는다. 배송비를
구매자에게 전액 청구하는지, 판매자가 일부 부담하는지, 무료배송 조건이 있는지를 별도
시나리오로 두며 공식·업체 버전이 바뀌어도 과거 계산은 기존 입력으로 재현한다.

## 5. 수집 SOP

### 5.1 발견

- `G1/G2`: 정부·공공기관 공식 검색, RSS, API, 고시·법령 변경 알림에서 후보를 만든다.
- `V1`: 업체의 공개 작업 가이드, 도움말, 가격/정산 공지 URL만 후보로 만든다.
- `E1`: 커뮤니티 질문은 `무엇이 비어 있는가`를 찾는 단서로만 쓰고 사실 필드를 만들지 않는다.
- 검색 결과 요약과 Pro/AI 답변은 모두 `U0`이며 URL 발견 보조 수단이다.

### 5.2 출처 등록

URL, 발행자, 계층, 관할, 문서 종류, 이용조건, robots 결과, 언어, 접근 시각,
예상 재확인 주기와 지원 가능한 필드를 먼저 등록한다. 출처가 필드를 지원할 권한이
없으면 접근 가능해도 후보를 보류한다.

### 5.3 획득·스냅샷

- 공개 API는 이용약관·호출 한도·재배포 조건을 기록하고 원 응답 해시를 남긴다.
- 공개 HTML/PDF는 조건을 허용하는 범위에서 비공개 원문 캐시와 정규화 텍스트의
  SHA-256을 남긴다. 공개 사이트에는 필요한 짧은 사실과 원문 링크만 생성한다.
- PDF는 파일 해시, 페이지, 표/별표 위치를 기록한다. OCR 결과만으로 법률·수치 필드를 승인하지 않는다.
- 개인 대시보드, 견적서, 계약서는 서버 수집 대상이 아니다. 계산기에 사용자가 직접 넣은
  값은 기본적으로 기기 로컬에 두고 공개 데이터와 분리한다.

### 5.4 필드 추출

자동 추출은 `candidateValue`, 단위, 원문 위치, 추출 방식, confidence를 만든다. `0`,
`무료`, `면제`, `불필요`는 원문이 명시한 경우만 쓸 수 있고, 부재는 `null`이다.
가격에는 통화, VAT 포함 여부, 옵션 서명, 최소 수량, 배송 포함 여부가 모두 필요하다.

### 5.5 사람 검수

- `G1` 의무·기한: 원문과 시행일을 두 번째로 확인하고, 적용 질문과 예외를 함께 검수한다.
- `G2` 안내: 법률 본문인지 기관 설명인지 표시를 확인한다.
- `V1` 사양·가격: 업체, 상품, 옵션, 기준일을 다시 열어 보고 캡처한 숫자가 현재 노출되는지 확인한다.
- 고위험 안전·세무 정보는 한 명의 편집 승인만으로 개인 결론을 만들지 않고 공식 상담/전문가 확인 경로를 둔다.

### 5.6 공개

공개 최소 조건은 `sourceTier`, 접근 가능한 원문, `checkedAt`, 적용 범위, 시행/기준일,
사람 검수, 불확실성 표시다. 하나라도 없으면 `research_candidate` 또는 `needs_review`로
남긴다. 계산기는 원본 입력과 가정을 사용자가 볼 수 있어야 한다.

### 5.7 변경 감지·재확인

- 해시 변경은 기존 값을 덮어쓰지 않고 검수 대기열을 만든다.
- 날짜가 임박한 세무·지원·판매채널 공지는 재확인 주기를 짧게 한다.
- `nextCheckAt`을 넘긴 고위험 레코드는 `stale`로 표시하고 자동 계산의 기본값에서 제외한다.
- 접근 실패는 사실의 거짓을 뜻하지 않지만 신규 공개와 자동 계산 사용을 막는다.

### 5.8 정정·이력

변경 전 값, 변경 후 값, 이유, 편집자, 시각, 원문 ID와 `supersedesId`를 append-only로
남긴다. 이전 법령·요금·업체 사양은 과거 계산 재현을 위해 삭제하지 않는다.

## 6. 자동 수집하지 않을 대상

- 로그인, CAPTCHA, 개인 판매자 등급, 정산 대시보드, 장바구니, 견적 계산기
- robots 또는 이용약관이 자동 접근·복제·재배포를 막는 페이지
- 개인 견적서, 계약 요금, 세금 신고서, 사업자등록증, 주소·연락처가 있는 민원 결과
- 뉴스레터·오픈채팅·카페·SNS의 원문을 동의 없이 복제한 자료
- 작가 실명과 주문량·매출·불량률을 연결할 수 있는 소표본 경험 데이터
- 폰트·템플릿·인쇄 가이드 원본 파일의 무단 미러링
- 동적 옵션을 고정 URL 하나로 재현할 수 없는 가격과 납기

이 대상은 사용자가 로컬 계산 입력이나 정정 제보로 직접 제공할 수 있지만, 그 경우에도
공개 사실 승격과 서버 보관은 별도 동의·권리·개인정보 검토 전까지 금지한다.

## 7. 8주 최소 데이터셋

목표는 레코드 개수가 아니라 **선택한 제품군에서 공개되는 모든 필드와 계산 결과가
원문·버전·확인일·검수자까지 역추적되는 것**이다. 파일럿 제품군은 스티커, 엽서·카드·
소형 인쇄물, 메모지, 아크릴 키링으로 제한한다.

### 1주차 — 데이터 계약과 범위

- `RegulatoryRuleVersion`, `ProviderClaimVersion`, `PrivateQuoteEvidence`,
  `CreatorExperienceReport`, `DerivedResultVersion`을 물리적으로 분리한다.
- `SourceRecord`, `SourceSnapshot`, `FieldEvidence`, 가격·납기 비교 가능성, `stale` 규칙을 확정한다.
- 공개/로그인/개별 견적 출처를 구분하고 불완전한 구성은 순위·계산에서 제외한다.

### 2주차 — 사양 온톨로지

- 완성/작업 크기, 도련, 안전영역, 반칼/완칼/재단, 소재·두께·투명·백색 인쇄,
  코팅·박·에폭시, MOQ, 파일형식·색상모드·레이어 규칙을 `SpecConcept`로 연결한다.
- 업체 원문 용어와 공통 개념을 함께 보존하고 `mappingConfidence`가 낮으면 비교하지 않는다.
- 가이드 설명·사진·템플릿을 재배포하지 않고 최소 사실과 원문 링크만 공개한다.

### 3주차 — 제작업체 카탈로그 1차

- 공개 1차 출처가 충분한 업체부터 `OfferingVersion`을 만든다.
- 수량·크기·재질·후가공·가격 기준·VAT·배송·납기 단계·확인일이 모두 있는 구성만 비교한다.
- `○원부터`는 단독 비교값으로 쓰지 않고 동일 구성 재현 절차를 검수 기록에 남긴다.

### 4주차 — 교차비교와 버전

- 같은 `SpecConcept`와 완전한 옵션 서명에 연결되는 상품만 나란히 표시한다.
- 가격·납기·옵션 삭제를 이전 버전을 덮어쓰지 않고 새 버전과 변경 후보로 저장한다.
- 제휴·광고 상태가 데이터 완성도나 기본 비교 정렬에 영향을 주지 않게 한다.

### 5주차 — 배송 레지스트리

- 우체국과 공개 1차 출처를 검수할 수 있는 편의점 서비스부터 시작한다.
- 중량, 크기, 지역, 접수 방식, 예상 기간, 제외품목, 보상 근거를 각각 연결한다.
- 공표 소비자 요금과 개인 계약요금을 분리하고 경계 중량·제주/도서·규격 초과를 테스트한다.

### 6주차 — 원가·손익 계산기

- 제작비·포장비·배송비·수수료·고정비·불량·샘플·증정·잔존 재고를 분리한다.
- `FormulaVersion`과 모든 입력 출처를 역추적하고 VAT 포함/별도/공제 가정을 명시한다.
- 판매 가능 수량 0, 음수 재고, 배송비 미확정, 단위공헌이익 0 이하를 숫자로 꾸미지 않는다.
- 대표 시나리오를 수기로 재계산하고 원문 가격 변경 전 계산을 그대로 보존한다.

### 7주차 — P1 공식 출처 팩

- 사업 시작·통신판매, 연간 세무 일정, 어린이 대상 가능 제품, 폰트·이미지·상표,
  온라인 상품 표시·반품·개인정보, 판매채널 수수료 구성의 체크리스트만 공개한다.
- 문항마다 현행 공식 출처와 적용일이 있고 KC·세무·개인정보는 2인이 검수한다.
- 최종 법률·세무·안전 결론을 내리지 않고, 현재 요율을 확인할 수 없으면 숫자를 노출하지 않는다.

### 8주차 — 변경감지·정정·출시 게이트

- 모든 P0 원자 필드가 `SourceRecord + SnapshotHash + 확인일 + reviewer`를 가진다.
- 가격·납기·요금 모의 변경이 새 버전과 영향받은 계산·저장 Notes를 식별한다.
- 정정 이력에서 구값·신값·사유·검수자·적용 시점을 확인하고 과거 계산을 재현한다.
- 경험 데이터가 공식·업체 기본값이나 순위를 바꾸지 않고 미검증 항목은 `확인 필요`로 보인다.

## 8. 출시하지 말아야 할 상태

- 세무 캘린더가 사용자의 과세유형을 묻지 않고 하나의 날짜만 제시함
- 상품명이 `스티커`라는 이유만으로 KC 비대상 또는 대상이라고 확정함
- 서로 다른 수량·재질·후가공·배송 조건의 업체 가격을 최저가로 비교함
- 스마트스토어 등급별·유입별 수수료를 대표 수수료 한 숫자로 고정함
- 업체가 공표한 납기와 작가의 실제 경험을 같은 평균값으로 합침
- 상표 검색 결과를 등록 가능 또는 비침해 보증으로 표현함
- FSC 소재나 재생지 사용만으로 완제품의 인증·친환경 표시 권한을 주장함

## 9. WebGPT Pro 협업 기록

2026-08-07 웹 ChatGPT의 `Pro` 모드에 현재 Bindery의 행사 데이터 규모, 공식/경험
분리 원칙, 후보 15개 영역, P0 제한, 필드·수집·갱신·위험·8주 데이터셋 요구를 전달했다.
Pro는 9개 웹사이트 조사 뒤 최종 P0를 `인쇄·후가공 사양 표준사전`, `제작업체 공표
카탈로그`, `포장·배송 레지스트리`, `재고·원가·손익 계산기`로 좁혔다. 사업자·세무·
KC·권리·온라인 판매 규정은 중요도가 낮아서가 아니라 적용 조건과 검수 책임이 커서,
초기에는 P1 공식 원문 체크리스트로 제한하라고 결론 내렸다. 이 문서는 그 결과를 현재
저장소의 FieldEvidence·변경감지·비공개 후기 경계와 결합하고, 별도로 확인한 공식
1차 출처만 시작 목록에 넣었다. 모델 답변과 검색 요약 자체는 공개 필드의 근거가 아니다.

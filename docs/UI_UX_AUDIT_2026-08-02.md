# Bindery UI/UX 감사 및 개선안

기준일: 2026-08-02  
대상 브랜치: `agent/bindery-product-strategy-review`  
대상 제품: 한국 독립 문구·일러스트 창작자 행사 데이터베이스 및 운영 지식 아카이브  
상태: 소스·디자인 시스템·반응형 계약 감사 완료, 실제 Sites 배포본 픽셀 검수는 배포 후 별도 게이트

## 0. 결론

Bindery의 UI는 흔한 행사 카드 포털이나 범용 SaaS 템플릿보다 정체성이 강하고,
정보 신뢰 경계와 접근성 설계도 우수하다. 현재 가장 큰 UX 위험은 시각 완성도가
아니라 **행사·노트·공동구매·뉴스·커뮤니티가 같은 무게로 보이면서 핵심 작업이
분산되는 것**, 그리고 **비교·아카이브처럼 가로로 넓은 데이터가 모바일에서
스크롤 가능하다는 사실이 충분히 드러나지 않는 것**이었다.

이번 변경은 제품의 첫 작업을 행사 비교와 회차 탐색으로 고정하고, 다음 문제를
직접 보완했다.

- 비교 전에 예시 데이터와 공식 원문 경계를 먼저 보여 준다.
- 표를 읽기 전에 가장 이른 마감, 낮은 참가비, 사업자 없이 신청 가능한 회차를
  요약한다.
- 모바일에서 좌우 스크롤 안내를 표시한다.
- 표 스크롤 영역을 키보드로 포커스할 수 있게 한다.
- 가로 스크롤 중에도 비교 항목 또는 회차 이름이 사라지지 않도록 첫 열을
  고정한다.
- 회차 아카이브 상단에 행사 바로가기 원장을 추가한다.
- 최신 회차를 표 안에서 명시적으로 표시한다.

현 상태의 UI는 **실제 행사 데이터가 들어오기 전 제품 검증 UI로는 높은 수준**이다.
다음 단계의 성패는 더 화려한 시각 효과보다 실제 데이터 밀도, 최신성 표시,
변경 이력과 검색·저장 루프에 달려 있다.

## 1. 평가 범위와 방법

### 1.1 검토 범위

- 홈과 전역 헤더·푸터
- 행사 목록, 달력, 상세
- 신규 행사 비교와 회차 아카이브
- Notes, News, Groupbuy, My Binder
- Community 허브와 공개·작가 게시판의 정보 경계
- `DESIGN.md`, `PRODUCT.md`, 테마 토큰과 전역 CSS
- 360px, 768px, 1280px 반응형 계약과 Playwright 검증 코드
- 키보드 포커스, 터치 타깃, 색상 대비, 표 스크롤과 의미 구조

### 1.2 방법

- 소스 구조와 실제 컴포넌트 마크업 검토
- 디자인 문서와 구현 간 일치 여부 확인
- 정보 위계, 다음 행동, 오류·신뢰 문구, 모바일 탐색 평가
- 테마 토큰의 WCAG 명도 대비 계산
- 기존 테스트가 보장하는 UX 계약과 누락된 계약 구분
- 신규 비교·아카이브 화면의 확장성 검토

### 1.3 검토 제약

현재 생산 Site는 소유자 전용이고 이 도구 세션에는 ChatGPT Sites 미리보기나
컴퓨터 조작 도구가 연결되어 있지 않다. 따라서 이번 감사는 저장소 소스와
스타일·테스트 계약을 기준으로 수행했다. 새 버전 배포 후에는 실제 360×800,
768×1024, 1280×900 렌더와 폰트 로딩, 스크롤, 포커스, 색상 토큰을 다시
확인해야 한다.

## 3. 잘된 점

### 3.1 정보 사이트다운 시각 언어

Bindery는 큰 사진 카드, 과도한 라운드, 그라디언트, 유리 효과, 장식 지표를
피한다. 대신 종이 면, 얇은 구조선, 날짜와 비용을 위한 고정폭 숫자,
Hahmlet 제목과 IBM Plex Sans KR 본문으로 정보의 물성을 만든다.

이 방향은 행사 티켓 판매 사이트가 아니라 **판단 자료를 축적하는 바인더**라는
제품 성격과 맞는다. 특히 같은 카드 그리드를 모든 섹션에 반복하지 않고
원장·표·달력·정의 목록을 구분한 점이 좋다.

### 3.2 홈의 절제

홈은 모든 기능을 펼치지 않고 다음만 보여 준다.

- 현재 날짜
- 가까운 마감 3건
- 비교와 회차 아카이브 진입
- 다섯 개 정보 축
- My Binder 진입

정보형 제품이 흔히 빠지는 대시보드 과밀을 피한다. “신청 마감을 놓치면 1년을
기다립니다”라는 문구도 사용자 손실을 구체적으로 설명해 첫 화면의 긴장감을
만든다.

### 3.3 신뢰 경계가 UI 안에 존재한다

공식 원문, 확인 날짜, 예시 데이터, 정보 없음, N<5 후기 비공개, 기기 초안,
미구성 백엔드, 작가 권한 실패 폐쇄가 화면에 직접 표현된다. 이는 별도 약관에만
숨겨진 경고보다 낫다.

행사 사이트에서 가장 큰 위험은 잘못된 마감·비용 정보를 확정 사실처럼 보이는
것이다. Bindery는 현재 이 위험을 제품 카피와 데이터 필드로 관리한다.

### 3.4 접근성의 기본기가 좋다

- 본문 건너뛰기 링크
- 전역 `:focus-visible` 3px 윤곽선
- 44px 터치 타깃
- 의미 있는 `nav`, `table`, `th scope`, `aria-current`
- 색상과 텍스트를 함께 쓰는 상태 표현
- `prefers-reduced-motion` 대응
- 360px에서 페이지 전체 가로 넘침을 막고 표·달력이 자체 스크롤을 소유

특히 작가 게시판을 시각 배지나 쿼리 값으로 열지 않고 서버 권한과 함께 실패
폐쇄한 점은 UX와 보안이 일치하는 사례다.

### 3.5 테마 대비

테마 토큰을 기준으로 계산한 주요 대비는 다음과 같다.

| 조합 | 리소 원색 | 먹지 교정 |
|---|---:|---:|
| 본문 `text` / `stock` | 13.37:1 | 14.15:1 |
| 보조 `textSoft` / `stock` | 5.07:1 | 6.10:1 |
| 희미한 `textFaint` / `stock` | 4.63:1 | 5.02:1 |
| 구조색 `inkBlue` / `stock` | 5.89:1 | 9.13:1 |
| 분홍 `inkPink` / `stock` | 2.47:1 | 4.62:1 |

기본 리소 테마의 분홍은 일반 본문 텍스트 대비를 충족하지 않으므로 현재처럼
마감 밑줄, 오프셋, 장식 신호로만 사용해야 한다. 본문·보조·희미한 텍스트와
파랑 구조색은 일반 크기 텍스트 기준을 충족한다.

## 4. 핵심 문제와 우선순위

## P0 — 출시 전에 반드시 유지할 계약

### 4.1 실제 데이터와 예시 데이터의 시각 구분

현재 예시 데이터라는 문구는 존재하지만, 비교표에서 사용자가 숫자를 보기 전에
경계를 인지해야 한다. 비교 결과 뒤에 경고를 배치하면 이미 숫자를 사실로
받아들인 뒤다.

**조치:** 비교 선택 직후, 비교 요약과 표보다 앞에 `예시 데이터` 경계를
배치했다. 실제 데이터 도입 시 이 자리는 `검증`, `재확인 필요`, `공식 출처
없음` 상태로 대체한다.

### 4.2 모바일 가로 표의 발견성

자체 스크롤만 구현하면 페이지 넘침은 막을 수 있지만, 사용자가 오른쪽 열의
존재를 알아차리지 못할 수 있다. 특히 비교표에서 첫 화면에 보이지 않는 행사가
있으면 기능 자체가 실패한다.

**조치:** 680px 이하에서 좌우 스크롤 안내를 표시하고, 스크롤 컨테이너를
`role="region"`, `aria-label`, `tabIndex=0`으로 노출했다. 비교 항목과 회차명은
첫 열에 고정했다.

### 4.3 비교 화면의 인지 부하

기존 구현은 세 개 선택기 다음에 11행 표가 바로 이어졌다. 사용자는 가장 급한
차이를 찾기 위해 모든 행을 훑어야 했다.

**조치:** 다음 세 신호를 표 앞에서 요약한다.

- 가장 이른 신청 마감
- 가장 낮은 참가비
- 사업자 없이 신청 가능한 선택 회차

이 요약은 행사 품질이나 추천 순위를 만들지 않고 값의 차이만 보여 준다.

### 4.4 아카이브의 길이 증가

현재 행사 수에서는 연속된 표도 읽을 수 있지만, 50개 행사·120개 회차 목표에
도달하면 상단에서 특정 행사를 찾기 어렵다.

**조치:** 카드 그리드가 아닌 선형 원장 형태의 `행사 바로가기`를 추가했다.
각 행에는 행사명, 회차 수, 확인 날짜가 있고 해당 표의 앵커로 이동한다.

## P1 — 실제 데이터 배치와 함께 구현

### 4.5 목록에서 최신성 판단이 부족하다

행사 목록은 마감, 참가비, 선정 방식은 잘 보여 주지만 공식 확인일과 정보
상태는 상세에 들어가야 확인할 수 있다.

**권장:** 행사 목록의 보조 정보에 다음 중 하나만 선택적으로 노출한다.

- `7월 24일 확인`
- `재확인 필요`
- `이전 회차 대비 +30,000원`

모바일에서는 모두 노출하지 말고 정렬·필터나 상태 한 개만 유지한다.

### 4.6 현재 섹션 표시가 없다

전역 헤더의 메뉴는 현재 위치를 시각적으로 표시하지 않는다. 하위 페이지에서
사용자가 어느 정보 축에 있는지 다시 읽어야 한다.

**권장:** 경로를 읽는 작은 클라이언트 내비게이션 컴포넌트를 두고 현재 1차
섹션에 `aria-current="page"` 또는 `aria-current="location"`과 얇은 파랑
밑줄을 적용한다. 모바일 메뉴에서도 동일한 상태를 제공한다.

### 4.7 테마 선택기의 우선순위

테마 선택은 브랜드 경험에는 도움이 되지만, 첫 방문자가 행사 찾기보다 먼저
결정해야 할 기능은 아니다. 데스크톱 헤더에서 정보 메뉴와 같은 시각 무게를
차지한다.

**권장:** 현재 기능은 유지하되 레이블을 더 작게 두거나 My Binder/설정 맥락으로
이동하는 A/B 검토를 한다. 사용 로그 없이 제거하지 않는다.

### 4.8 행사 상세의 변경점 요약

현재 상세는 신청·현장·회차 이력이 풍부하지만 “지난 회차에서 무엇이
달라졌는가”를 사용자가 직접 표에서 찾아야 한다.

**권장:** 공식 출처 아래에 운영자가 승인한 변경 요약을 둔다.

- 참가비 `+30,000원`
- 장소 `C홀 → A홀`
- 선정 `선착순 → 심사`
- 사업자 조건 변경

자동 diff는 초안만 만들고 공개는 운영자가 승인한다.

### 4.9 이미지가 전혀 없는 상태의 한계

정보 우선 방향은 맞지만 행사 포스터, 공식 배치도와 현장 사진은 회차를
식별하고 준비하는 데 실제 정보 가치가 있다.

**권장:** 이미지가 핵심 사실보다 앞서지 않도록 상세 본문 안에서 사용한다.

- 대표 포스터: 행사 마스터가 아니라 회차에 귀속
- 배치도: 원본 링크와 확인 날짜 제공
- 현장 사진: 반입·부스·동선 설명과 연결
- 권리 불명확: 이미지 재게시 없이 공식 원문 링크만 제공

## P2 — 데이터 밀도 확보 후 실험

### 4.10 개인화 추천

현재 데이터 수에서 AI 추천을 전면에 두면 근거가 빈약하고 행사 적합도를
과장할 위험이 있다. 추천은 다음 전제 뒤에 실험한다.

- 검증 행사 마스터 150개 이상
- 사용자 선택·저장·공식 원문 이동 로그
- 추천 제외 이유와 근거 필드 표시
- 잘못된 추천 사례 평가 세트

### 4.11 커뮤니티의 시각적 비중

커뮤니티 기능은 안전 설계가 강하지만 홈·검색·알림에서 과도하게 성장시키면
Bindery가 행사 아카이브가 아니라 일반 게시판으로 인식될 수 있다.

**권장:** 커뮤니티 글을 독립 인기 순위로 밀기보다 관련 행사·노트의 공백을
채우는 방식으로 연결한다. 해결된 질문과 출처 있는 답변만 지식 승격 후보로
다룬다.

## 5. 화면별 평가

### 5.1 홈

**잘된 점**

- 한 문장과 세 개 마감으로 역할이 즉시 보인다.
- 색상 사용이 절제돼 D-day가 눈에 띈다.
- 다섯 개 인덱스가 카드 광고처럼 보이지 않는다.

**주의점**

- 비교 CTA는 데이터가 적을 때 빈 기능처럼 보일 수 있다.
- 실제 데이터 도입 전에는 `행사 전체 보기`보다 비교를 강하게 미는 근거가
  약할 수 있다.

**검증 지표**

- 홈 → 비교 이동률
- 비교에서 2개 이상 선택 완료율
- 홈 마감 행 → 상세 이동률

### 5.2 행사 목록

**잘된 점**

- 필터가 URL과 동기화돼 공유와 뒤로 가기가 안정적이다.
- 마감·참가비·선정 방식이 한 행에서 비교된다.
- 모바일에서 핵심 두 필드를 유지하고 덜 중요한 선정 열을 숨긴다.

**다음 개선**

- 공식 확인일 또는 최신성 상태
- Binder에서 바로 비교 목록으로 보내는 행동
- 무결과 필터에서 유사 조건 제안

### 5.3 행사 비교

**이번 변경 후 구조**

1. 행사 선택
2. 예시/검증 경계
3. 의사결정 요약
4. 전체 조건표
5. 공식 원문

이 순서는 사용자가 숫자를 믿기 전에 데이터 상태를 이해하고, 표를 훑기 전에
가장 큰 차이를 파악하게 한다.

**남은 과제**

- 부스 유형이 여러 개인 실제 행사 모델
- 가장 싼 값이 아니라 동일 부스 유형 비교
- 차이가 있는 셀만 강조하는 모드
- Binder 저장 행사 불러오기

### 5.4 회차 아카이브

**이번 변경 후 개선**

- 행사 바로가기
- 회차 수와 확인일
- 최신 회차 앵커와 현재 회차 표시
- 키보드 포커스 가능한 표
- 모바일 스크롤 안내와 첫 열 고정

**남은 과제**

- 행사 마스터와 회차 URL 분리
- 회차 날짜의 정규화된 정렬
- 변경점 타임라인
- 포스터·공지의 출처와 권리 이력

### 5.5 행사 상세

**잘된 점**

- 공식 원문 바가 제목 바로 아래 있다.
- 신청 준비와 현장 준비가 작업 순서에 맞는다.
- 고정 사이드바가 결정 필드를 반복한다.
- N<5 후기 비공개가 명확하다.

**다음 개선**

- 현재 회차 대비 이전 회차 변경 요약
- Binder 저장 후 다음 행동: 비교, 달력, 준비 노트
- 모바일에서 긴 표의 스크롤 안내 통일

### 5.6 Community

**잘된 점**

- 작가 자격과 정보 사실성을 구분한다.
- 작가 게시판은 콘텐츠까지 실패 폐쇄한다.
- 권한·신고·이의제기·수정 이력이 UI와 데이터베이스 계약으로 연결된다.

**주의점**

- 인증, 운영, 알림, 신고 화면의 수가 핵심 행사 화면보다 많아질 수 있다.
- 실제 사용자가 적은 단계에서 운영 기능을 더 늘리는 것은 우선순위가 아니다.

## 7. 출시 검증 게이트

병합·배포 전후에 다음을 확인한다.

### 자동 검증

- `npm run lint`
- `npm run typecheck`
- `npm test`
- `npm run build`
- 비교·아카이브 Playwright 테스트
- 기존 Community와 Binder 회귀 테스트

### 실제 화면

#### 360×800

- 페이지 전체 가로 스크롤 없음
- 비교·아카이브 표만 가로 스크롤
- 좌우 스크롤 안내가 보임
- 첫 열이 스크롤 중 고정
- 선택기 글자 16px 이상 또는 브라우저 확대 방지 조건 충족
- CTA와 메뉴 조작 높이 44px 이상

#### 768×1024

- 헤더가 모바일 내비게이션으로 전환
- 비교 선택기 2열이 과도하게 좁지 않음
- 요약 3열이 읽을 수 있는 폭을 유지
- 아카이브 메타가 한 줄 과밀을 만들지 않음

#### 1280×900

- 페이지 폭 1120px 안에서 비교표 열이 균형을 이룸
- 행사 바로가기 원장이 카드 그리드처럼 보이지 않음
- 제목과 섹션 사이 여백이 기존 페이지와 일치
- 외부 폰트 실패 시 레이아웃 급변 없음

### 상호작용

- 탭 키로 비교 선택기 → 적용 → 초기화 → 표 region 이동
- 표 region 포커스 링 확인
- 키보드 화살표 또는 트랙패드로 가로 이동
- 앵커 이동 후 행사 제목이 sticky header 아래에 가려지지 않음
- 테마 변경 뒤 표의 sticky 셀 배경과 대비 유지

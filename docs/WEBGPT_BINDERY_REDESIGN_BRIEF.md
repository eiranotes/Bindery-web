# Bindery WebGPT Pro Redesign Brief

## 목적

이 문서는 WebGPT Pro가 현재 Bindery 웹사이트를 실제 소스와 제품 정책에
맞춰 감사하고, 바로 구현 가능한 개선안을 제시하도록 주는 프로젝트 소스다.
새 사이트를 처음부터 만드는 요청이 아니다. 현재 vinext/React 구조와 공식
행사 데이터 파이프라인을 유지한 채 정보 위계와 전역 UI를 고친다.

- 소스 저장소: <https://github.com/eiranotes/Bindery-web>
- 공개 정적 프리뷰: <https://eiranotes.github.io/Bindery-web/>
- 기본 사용자: 한국의 1인 창작자와 소규모 굿즈 판매자
- 핵심 작업: 행사 신청 마감·비용·조건 확인, 행사 비교, 과거 회차 변화 확인

## 이번 개선에서 고정된 제품 우선순위

1. 행사 공식 정보와 확인 시점
2. 행사 비교와 회차 아카이브
3. 계정 없이 쓰는 Binder·ICS·URL 필터
4. 준비 기준을 정리한 Notes와 공식 News
5. 관련 행사·노트의 공백을 보충하는 Community
6. Groupbuy와 광고

이번 릴리스에서 Groupbuy는 삭제하지 않지만 전역 내비게이션, 홈 인덱스,
검색 노출과 사이트맵에서 가린다. Community는 운영 기능을 유지하되 행사
탐색을 방해하지 않는 보조 탐색으로 내린다.

## 사용자 요구

- 메인 워드마크는 한글 `바인더리`가 아니라 정확히 `Bindery`로 표기한다.
- 한국어를 기본으로 두고 영어(`en`), 일본어(`ja`), 중국어 간체(`zh`)를
  확장할 수 있는 다국어 스켈레톤을 만든다.
- 다국어가 아직 적용되지 않은 본문을 번역된 것처럼 보이게 하지 않는다.
- UI 색은 중성 표면, 본문 잉크, 구조용 파랑, 마감용 분홍을 중심으로
  3~4개 역할 색만 사용한다. 노랑·초록·보라의 장식적 사용을 제거한다.
- 최신 웹 제품 UI 흐름과 Apple 인터페이스 원칙을 조사하되, 유리 효과,
  그라디언트, 큰 라운드 카드, 과장된 히어로, 장식 애니메이션을 복제하지
  않는다.
- 행사 공식 원문, 확인 날짜, `정보 없음` 경계를 시각 장식보다 우선한다.

## 현재 구현에서 확인할 파일

- `PRODUCT.md`: 제품 대상, 목적, 우선순위와 운영 경계
- `DESIGN.md`: 현재 리소 인쇄 기반 디자인 시스템과 접근성 기준
- `docs/SITE_STRATEGY_AND_ROADMAP.md`: 행사 데이터 중심 로드맵
- `docs/UI_UX_AUDIT_2026-08-02.md`: 기존 UI 감사와 남은 과제
- `docs/CONTENT_PIPELINE.md`: 공식 정보와 로컬 후기 수집 분리 원칙
- `app/components/SiteHeader.tsx`: 현재 5개 축을 같은 급으로 노출하는 헤더
- `app/components/SiteFooter.tsx`: 보조 탐색
- `app/page.tsx`: 행사, 노트, 공동구매, 소식, 커뮤니티 5개 홈 인덱스
- `app/lib/themes.ts`: 현재 여러 색 역할을 가진 테마 카탈로그
- `app/globals.css`: 전역 레이아웃과 상태 스타일
- `app/sitemap.ts`: 공개 검색 경로
- `scripts/export-pages.mjs`: GitHub Pages 정적 프리뷰 경로 목록

## 현재 디자인에서 보존할 것

- 최대 1120px 콘텐츠 폭과 선형 원장·표·목록 중심 구성
- Hahmlet 제목, IBM Plex Sans KR 본문, Space Mono 메타데이터
- 2px 이하 radius, 그림자 대신 얇은 선과 표면 차이
- 마감 3건만 보여 주는 홈과 D-day 미스레지스트레이션 상호작용
- 공식 출처·확인 날짜·예시/검증 경계를 설명하는 신뢰 UI
- 360px, 768px, 1280px 반응형 기준, 44px 터치 타깃과 키보드 포커스

## 현재 문제

- 제품 문서는 행사를 1순위로 정했지만 전역 헤더는 행사, 노트, 공동구매,
  소식, 커뮤니티를 같은 수준으로 보여 준다.
- 홈의 다섯 인덱스도 공동구매와 커뮤니티를 행사 도구와 같은 급으로 보이게
  한다.
- 기본 테마는 파랑·분홍·노랑 외에도 보라·초록과 여러 중성 토큰을 별도
  색으로 취급해 사용자 요구보다 다채롭다.
- 워드마크가 `바인더리`이고 다국어 확장 구조가 없다.
- 정적 Pages 프리뷰는 애플리케이션 JavaScript를 제거하므로 서버·계정·
  저장·언어 선택 같은 동적 기능을 제공하지 않는다. 프리뷰에서 이를
  정직하게 표시해야 한다.

## Pro 모델에 요청할 조사

1. 2025~2026년 현재 웹 정보 제품에서 유효한 흐름을 Apple HIG, W3C/WCAG,
   브라우저 플랫폼 문서, 신뢰할 수 있는 디자인 시스템 같은 원문 중심으로
   조사하고 링크와 확인 날짜를 제시한다.
2. Apple 디자인 원칙 또는 웹사이트 디자인에 적용 가능한 현재 스킬·가이드를
   찾아 이 제품에 맞는 항목과 맞지 않는 항목을 구분한다.
3. 최신이라는 이유만으로 glassmorphism, bento card, 큰 타이포, scroll
   choreography를 권하지 말고 행사 판단 속도와 신뢰를 기준으로 평가한다.
4. 아래 형식으로 구현 가능한 답을 낸다.
   - P0/P1/P2 감사 결과
   - 보존할 요소
   - 정보구조와 전역 탐색안
   - 4색 이내 역할 팔레트와 대비 근거
   - 다국어 스켈레톤의 단계별 범위
   - 정확한 파일별 변경안
   - 360/768/1280, 키보드, 모션 감소, 정적 Pages 검증 기준

## 구현 제약

- 현재 프레임워크와 데이터 흐름을 유지하고 새 UI 프레임워크를 추가하지 않는다.
- Groupbuy 코드는 삭제하지 않는다. 사용자가 승인할 때까지 후단 기능으로 둔다.
- Community 백엔드와 권한 코드는 재작성하지 않는다. 노출 위계만 낮춘다.
- 다국어는 전역 셸부터 단계적으로 적용하고, 미번역 행사 본문은 한국어로
  남아 있음을 명시한다.
- 공식 행사 필드를 자동 생성하거나 샘플 값으로 채우지 않는다.
- 공개 배포 전에 lint, typecheck, 테스트, build와 실제 브라우저 반응형 검증을
  다시 수행한다.
